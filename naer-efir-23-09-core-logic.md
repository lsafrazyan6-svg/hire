# Логика «Библиотеки референсов» — как устроен разбор референса

Свод по транскрипту эфира + тому, что уже реализовано в артефакте [Reference Library](https://claude.ai/artifact/EkNKuEcizYiMY26NWKeZsX). Это не общая теория — конкретный алгоритм, который использовали Миша и Даня.

## 1. Главный принцип — без него всё остальное не работает

Агент не умеет судить, что «красиво». Прямая цитата из эфира про это:

> «Ни Клод, ни Кодекс не знают, что значит "лучшие рефы индустрии". Он не понимает, что такое красиво, он вам красиво не воспроизведёт... Отправляете его искать рефы — архитектурно он классно подберёт, но сравнить "этот классный, а этот послабее" — не сможет.»

Значит вся логика разбора строится не на «агент сам оценил», а на: **владелец сначала сам объясняет текстом, что именно ему нравится и почему** — и только это объяснение агент раскладывает по полочкам. В артефакте это жёсткое требование: поле «Что нравится и почему» обязательно перед запуском разбора, без него кнопка «Разобрать» отказывает с объяснением.

## 2. Жизненный цикл одного референса — три стадии

1. **Исходник загружен** — просто картинка/видео + название, разбора ещё не было.
2. **Разобран** — прошёл текстовый анализ: определена механика (что/почему/как работает), проставлены теги, референс отнесён к подборке.
3. **Собран** — референс воспроизведён как рабочий компонент, который агент теперь может забирать в другие задачи по MCP.

На карточке это — три точки/полоски прогресса (подтверждено цитатой в транскрипте, не выдумано). Стадия не откатывается назад автоматически.

## 3. Разбор — что именно делает агент и почему он дешёвый

- Технически — прямой вызов API с ключом чат-модели (не MCP), потому что это лёгкая, частая операция; MCP дороже и предназначен только для сборки.
- На входе: картинка/кадр видео + объяснение владельца.
- На выходе (в артефакте — JSON от Claude):
  - **теги** (3–5, коротко),
  - **подборка** — выбор среди уже существующих у владельца подборок, агент не изобретает новую от себя,
  - **механика** — 2–3 предложения, разворачивающие объяснение владельца, а не придумывающие новую причину,
  - **приёмы** — 2–4 пункта в повелительном наклонении, специально в форме, которая работает без картинки («Ставить причину доступа до системного диалога») — именно эти строки потом копируются в файл с приёмами (кнопка «Скопировать как Markdown» в карточке).
- Явное ограничение агенту в промпте: не выдумывать точные цвета/отступы, если их не видно чётко — соответствует правилу «не выдумывай значения, нет в источнике».

## 4. Как ищут сами референсы (не автоматизировано в артефакте, это ручная практика)

Не спрашивают у основного агента «сделай красиво» — идут в **Grok**, который ищет по индексу X/Twitter, и просят свободным языком: «найди примеры для веба, как карточка скейлится zoom-транзишном, в идеале — с исходным кодом». Дальше открытый source code с найденного поста отдаётся основному агенту напрямую со ссылкой — воспроизвести эффект. Это внешний шаг относительно самого приложения «Библиотека», в артефакт не встроен (и не должен быть — Grok/Twitter вне зоны действия этой страницы).

## 5. Подборки — не таксономия, а живые папки владельца

Подборки не фиксированный список категорий — это папки, которые сам владелец создаёт и называет, а агент при разборе **сам** относит новый референс к одной из них, если подходит. В артефакте это реализовано именно так: раздел «Подборки» в сайдбаре — список из базы данных, разбор пытается сматчить название подходящей подборки, но никогда не создаёт новую от себя.

## 6. Сборка — то, что артефакт физически не может сделать сам

Реальная сборка — это отдельный, дорогой прогон через MCP, который пересобирает референс в рабочий React-компонент прямо в кодовом агенте (Кодекс/Клод), а не внутри веб-страницы Artifact. Страница-артефакт не может запускать MCP или писать код за пределы себя, поэтому стадия «Собрано» здесь — это честная ручная отметка (с необязательной заметкой, как именно собрали), а не имитация настоящей сборки. Это сознательное ограничение, не баг.

## 7. Что из этого уже реально работает в артефакте, а что — только вёрстка

| Логика | Статус в артефакте |
|---|---|
| Обязательное объяснение «что нравится и почему» перед разбором | ✅ работает, блокирует кнопку |
| Разбор через реального Claude по картинке | ✅ работает (`sample` capability) |
| Авто-теги, авто-подборка, механика, приёмы | ✅ работает, пишется в базу |
| Экспорт приёма в Markdown для вашего файла принципов | ✅ работает (кнопка в карточке) |
| Прогресс по 3 стадиям | ✅ работает |
| «К сборке» / «К просмотру» как фильтр по стадии | ⚠️ моя интерпретация по названиям — точное поведение по кадрам не подтверждено |
| Реальная сборка компонента (MCP → код) | ❌ невозможно внутри Artifact — стадия помечается вручную |
| Поиск референсов через Grok/X | ❌ вне артефакта, ручной внешний процесс |

## Открытый вопрос к вам

«К сборке» и «К просмотру» я сейчас трактую как: К просмотру = только что добавленные, ещё не разобранные; К сборке = разобранные, ждут сборки. Если по факту в приложении это работает иначе — поправьте, это единственное место, где я осознанно интерпретировал, а не подтвердил по кадру/речи.
