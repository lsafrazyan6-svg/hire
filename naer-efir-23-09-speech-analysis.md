# Разбор речи: как агенту дают указания и учат анализировать референсы

Источник: `transcript.txt` (whisper-расшифровка без пунктуации по строкам, 6661 строка), эфир «GPT-6 Astra + Миша Наер из Сбера», 23.09.2026. Ниже — по смыслу, не дословный пересказ.

## 1. Главное правило: объяснять, а не показывать

Даня прямо формулирует это как принцип, который нарушают чаще всего:

> «Важно объяснять агенту, что именно тебе понравилось в этом исходнике, почему это работает, потому что многие закидывают, говорят: красиво, хочу так же — агент не понимает вообще, что ты имеешь в виду, с трудом он воспроизводит какой-то классный качественный результат.»

То есть сама механика «закинул референс» — не работает без текстового объяснения **что конкретно нравится и почему**. Это прямой ответ на вопрос со слайда ~80 мин («Какой контекст нужен агенту, чтобы повторить эффект без угадывания?») — контекст этот текстовый, ручной, не автоматический.

## 2. Пайплайн разбора одного референса (ядро продукта)

Два отдельных этапа, разные механизмы, разная стоимость:

1. **Разбор** — агент смотрит на референс (картинку/видео), описывает его, определяет что/почему/как работает механика. У Дани это сделано через прямой API (дешёвый чат-модельный ключ). Заодно агент сам проставляет теги и категорию, определяет, к какому разделу/подборке относится референс.
2. **Сборка** — финальная пересборка референса в переиспользуемый компонент, который агент потом может забирать в другие задачи. Идёт через MCP — «более трудоёмкий процесс, по API это выйдет слишком дорого, поэтому делаем это со своей подпиской».

Видео разбирается дольше картинки — «декомпозирует только по кадрам», под это у Дани написан отдельный алгоритм.

### Три стадии referencing — разгадка индикатора-точек на карточке

В визуальной спецификации я отметил, что не понимаю назначение трёх точек под превью карточки. В транскрипте прямой ответ:

> «Также здесь отмечено три стадии: первая — просто когда ты закинул исходник, у нас одна здесь полосочка; вторая — когда он уже разобран именно в текстовом виде; третья — это когда уже воспроизведён.»

То есть три точки/полоски = прогресс по пайплайну «исходник → разбор → сборка», а не что-то декоративное. Нужно поправить визуальную спецификацию этим пунктом (сделаю).

## 3. Как ищут сами референсы — приём с Grok

Ключевая практика Миши, повторена дважды на двух разных проектах (библиотека референсов и книжка «Нара»):

- Не спрашивать у Клода/Кодекса напрямую «сделай красиво» — у модели нет вкуса, и она не умеет сравнивать эстетическое качество (см. п. 5).
- Вместо этого идти в **Grok** и просить его искать в Twitter/X: «найди мне примеры для веба, как карточка из ленты скейлится с zoom-транзишном, как в Pinterest, покажи примеры постов в X и в идеале — чтобы была библиотека или исходный код».
- Grok использует API Твиттера как базу для поиска, поэтому находит открытый код, который разработчики сами выкладывают с визуальными демками — то, что нужно: не просто картинка, а рабочий source code.
- Дальше — берётся ссылка на исходник/репозиторий и напрямую отдаётся основному агенту (Клоду/Кодексу) с просьбой воспроизвести эффект.

Прямая цитата про суть подхода: «Промпт-инжиниринга как такового нет. Ты просто разговариваешь как с чувачком… промпт-инжиниринг у вас на уровне среды — как у вас устроена среда, ровно настолько хорошо она работает; то, что вы пишете в качестве промпта, уже вообще не так важно».

## 4. Что агент не умеет (важно для трезвой оценки готового продукта)

Ближе к концу эфира в Q&A прямо разобрали ограничение, которое отвечает на второй вопрос со слайда ~80 мин («что осталось стоковым»):

> Вопрос: «Mobin MCP разочаровывает в Кодексе, когда просишь сделать редизайн по лучшим рефам индустрии — что не так?»
> Ответ Миши: «Ни Клод, ни Кодекс не знают, что значит «лучшие рефы в индустрии» — лучшие по чему? По выручке, по UI, по UX?.. Он не понимает, что такое «красиво», он вам красиво не воспроизведёт. Если отправляете его искать рефы — архитектурно он классно подберёт (может по flow поискать на Mobin, найти кучу примеров онбординга), но сравнить «этот классный, а этот послабее» — не сможет. Максимум по количеству текста разве что.»

Вывод: агент хорош на этапе **поиска по структуре/флоу**, но не на этапе **эстетической оценки/выбора** — эту роль всегда берёт на себя человек, объясняя вкус вручную (п. 1).

## 5. Организационные приёмы, не специфичные для одного продукта

- **GitHub вместо zip** как канал передачи контекста между Даней и Мишей — не только код, но «всю подсреду проекта, включая контекст, артефакты» — чтобы у второго агента на старте уже было понимание, что за продукт и что мы пытаемся сделать. Это прямая рекомендация для нашей же задачи (у нас сейчас похожая проблема — передача контекста между сессиями).
- **Сначала — компонентная база**, свой стиль потом. И Миша (Fluid Functionalism), и Даня (ShadCN) в самом начале переезжают на готовую качественную библиотеку компонентов («сайдбары, цвета, ховеры, селекты, кнопки — по максимуму готово»), чтобы не тратить время на базовые примитивы, а сфокусироваться на том, что реально отличает продукт — на референсах-контенте.
- Иконки, стиль карточек, элементы — тоже берутся у существующих качественных reference-приложений: Миша прямо называет источник вдохновения для карточек-референсов — продукт **Atlas** Алексея Сикачева (бесконечный канвас, zoom-transition с карточки на список) и сайт **interactionkit.org**, откуда взят рабочий source code для эффекта.
- **«Canvas»-скилл Дани** — отдельный, не входящий в сам продукт «Библиотека референсов»: «я собрал скилл, который мне по каждому проекту автоматически этот канвас собирает, чтобы было удобнее проводить навигацию, объяснять что сделано, собирать все эти артефакты». **Это и есть вьюер «Путь продукта» / `127.0.0.1:4380`**, который я описывал в визуальной спецификации — важная поправка: это не экран самого продукта «Библиотека референсов», а отдельный мета-инструмент Дани для документирования любого проекта. Для клона именно «Библиотеки референсов» этот экран, вероятно, не нужен воспроизводить как часть продукта — но метод (авто-генерируемый журнал с артефактами) сам по себе полезен и явно перекликается с целью HANDOFF по доске вайрфреймов/журналу.
